# ADAM RUN · первый рабочий этап

Flutter-приложение для iOS/Android и FastAPI. Регистрация/вход по email с **тестовым кодом `00000`**, рабочая главная, системный шагомер, один Walk Quest и один Run Race. Остальные пункты нижнего меню отображаются как «скоро» и никуда не ведут.

## Запуск

Нужны Flutter 3.47.5 / Dart 3.13.4, Python 3.13+, Java 21 для Android, Xcode для iOS. Минимальные ОС: Android 9 и iOS 15.5. Версии пакетов зафиксированы в `mobile/pubspec.lock` и `backend/requirements.txt`.

```sh
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```sh
cd mobile
flutter pub get
flutter run
```

По умолчанию Android эмулятор использует `http://10.0.2.2:8000`, iOS Simulator — `http://127.0.0.1:8000`. Для физического устройства запустить API с `--host 0.0.0.0` в доверенной локальной сети и передать адрес компьютера:

```sh
flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8000
```

Для web-проверки интерфейса: `flutter run -d chrome --web-port=7357`. В браузере шагомер недоступен — приложение показывает это явно. Настоящие шаги проверяются на телефоне.

## Что работает

- Регистрация с никнеймом, вход, сохранение сессии в защищённом хранилище, ротация refresh-токена, выход. Код действует 5 минут, максимум 5 попыток; повторное использование и старый код после повторного запроса запрещены. Запросы ограничены по email/IP.
- Главная: реальные шаги, цель 1 000–50 000, последние 7 дней, серия по доступной истории, переключение режимов, карта, локальная коллекция, личное время Run Race.
- Walk Quest **«Городская птица»**, около 5,38 км; Run Race **«Парковый Sprint»**, около 1,23 км. Оба — демонстрационные маршруты по геометрии пешеходных путей OSM. Партнёров и рекламных предложений нет.
- MapLibre с локальной картой центра Бишкека: графитовые кварталы, зелёные парки, оранжевая трасса. Для этой области тайлы и API-ключи не нужны. Web-библиотека MapLibre GL также включена локально (версия 5.6.2).
- Старт возле начала пути, контроль качества GPS, последовательное заполнение рисунка, пауза/продолжение, восстановление незаконченного прохождения после перезапуска. Запись маршрута автоматически приостанавливается в фоне; шагомер работает независимо.
- Завершение только после прохождения последовательных участков. +200 локальных XP и птица выдаются один раз. Это тестовые локальные достижения, не серверная антифрод-проверка и не партнёрские награды.

## Шагомер

- **iOS:** `CMPedometer` (Core Motion), точный системный счётчик телефона и история от локальной полуночи. История восстанавливается после закрытия приложения. Шаги Apple Watch сюда не прибавляются.
- **Android:** агрегированный `StepsRecord.COUNT_TOTAL` из Health Connect, без повторного суммирования источников. На Android 14+ с SDK Extension 20+ Health Connect может самостоятельно записывать шаги телефона. На старых устройствах нужны данные совместимого приложения или резервный датчик.
- **Резерв Android:** `TYPE_STEP_COUNTER` в foreground service с уведомлением; сохранение базы счётчика и дневных значений, обработка перезагрузки/смены даты. Учитываются только наблюдаемые при подключённом датчике шаги. Интервал через полночь/перезагрузку, который нельзя точно разделить, не приписывается текущему дню; интерфейс отмечает неполное покрытие.
- GPS, расстояние и движения экрана **не используются для расчёта шагов**. Нет датчика/разрешения — нет выдуманного числа. Системные шаги обновляются каждые 15 секунд и при возврате в приложение; Health Connect может обновляться с задержкой.

Нулевую погрешность обещать нельзя: она зависит от телефона и положения устройства. Перед выпуском нужен контрольный проход с ручным подсчётом на реальном Android/iPhone, включая заблокированный экран, перезапуск, отказ в разрешении и переход через полночь. Симулятор не проверяет точность физического датчика.

```sh
cd backend
.venv/bin/python -m pytest -q
cd ../mobile
flutter analyze
flutter test
flutter build apk --debug
flutter build ios --simulator --no-codesign
cd android
```

Интеграционная проверка на запущенном iOS Simulator (API должен работать на `127.0.0.1:8000`):

```sh
cd mobile
flutter test integration_test/app_test.dart -d <simulator-id>
```

Она создаёт тестового пользователя, проходит вход `00000`, проверяет защищённое хранилище и канал шагомера, сохраняет цель на сервере и переключает оба режима.

## Ограничения этапа

API использует SQLite для локального запуска; `DATABASE_URL` поддерживает PostgreSQL через psycopg. Начальная схема создаётся при старте. До изменения схемы с реальными данными следует добавить миграции. API хранит email, никнейм, цель и сессии. GPS-прогресс и игровые результаты пока только на устройстве; серверной синхронизации истории, QR, рейтингов, призов и партнёров нет.

Фиксированный OTP разрешён при `APP_ENV=development/test/demo` и `TEST_AUTH_ENABLED=true`; в production API отказывается стартовать с фиксированным кодом. Для размещённого demo обязательны отдельный случайный JWT_SECRET и постоянная PostgreSQL. Письма не отправляются, владение email не проверяется: код `00000` предназначен только для тестовых аккаунтов. Для настоящих пользователей нужен email-провайдер.

Развёртывание и подписанная APK: [docs/deployment.md](docs/deployment.md).

Городские маршруты требуют проверки на месте перед публичным запуском. Высота зданий на карте декоративная. Источники и лицензии: [docs/data-sources.md](docs/data-sources.md).
